# Per-account folders for the Authenticator fork

Adds an optional `folder` string to each OTP entry and groups the popup account list into collapsible folder sections, with an "Ungrouped" bucket for folderless accounts. The field is modeled as a strict mirror of the existing `pinned` field so it rides inside the per-entry `OTPStorage` object in `chrome.storage.sync` with no schema migration: writes are additive and emitted only when the folder is non-empty, reads default to `""`. Assignment happens inline in an entry's edit area and in the add-account advanced section, persisting the same way `pin()` does. The accordion is a presentation layer layered on top of the unchanged pinned-first `entries` getter, not interleaved dragula rows.

Watch for: within-folder drag-reorder is intentionally disabled whenever any folder exists (confirmed) — reorder only works in the flat no-folders view. The new storage round-trip test is proven to compile into the webpack test bundle but was not executed by the Puppeteer runner (confirmed), so its runtime pass is asserted by code reading, not a green test run. Old installs on another synced profile that re-save an entry will drop `folder` (likely, inherent to the sync model).

**Verdict**: APPROVED

## High-level view

The persistence design is the load-bearing decision and it holds up. `folder` is declared next to `pinned` on every interface and class, written by `getOTPStorageFromEntry` only when truthy, and read back by both `EntryStorage.get` and `import`. Crucially `backupGetExport` still deletes `pinned` but does not delete `folder`, so folder names survive cloud and file backups while the extension's own export-trimming behavior is otherwise untouched. Nothing migrates; an entry that never gets a folder keeps its exact current bytes.

The UI splits cleanly along a single condition. When no folders exist the original single `v-dragula` list renders verbatim — same drake, same keyboard handlers, same `no-entry` empty state, same `dropModel → moveCode → EntryStorage.set` reorder flow — so the common case is behaviorally identical to `dev`. When at least one folder exists, a separate non-dragula accordion renders instead, so drag-reorder silently stops being available rather than corrupting indices. That trade-off is deliberate and documented; it is the one behavioral regression a reviewer should weigh.

Assignment mirrors pinning on both surfaces: the inline editor commits `accounts/setFolder` then awaits `EntryStorage.set`, exactly like `pin()`, and the add page threads `folder` through the `OTPEntry` constructor. Collapse state lives in Vuex (`collapsedFolders`) and is never written to storage, so it does not sync — a reasonable scope choice for view state.

Scope is clean: no `archived` field or archive UI, no rebrand of name/manifest/icons, no changes to cloud-backup credentials, MIT `LICENSE` intact. Build and lint evidence in the FEAT files was reproduced here (webpack compiled successfully, eslint exit 0, prettier clean).

### Required-interface deviation from the `pinned` mirror

One deliberate deviation from a pure mirror: `OTPEntryInterface.folder` is declared **required** (`folder: string`), not optional. The FEAT-001 findings record that an optional declaration broke the build with TS2345 at three call sites in `Accounts.ts` plus `otp.ts`, because `OTPEntry.folder` is required and an optional interface field is not assignable to it. The existing `pinned` is likewise required on the interface, so making `folder` required is the faithful mirror. `RawOTPStorage.folder` stays optional, matching `pinned?`. Types-only; no runtime effect.

### Persistence and backup round-trip

```
set:    getOTPStorageFromEntry → if (entry.folder) storageItem.folder = entry.folder   // write only when truthy
get:    new OTPEntry({ ..., folder: entryData.folder })  where entryData.folder = data[hash].folder || ""
import: entryData.folder = data[hash].folder || ""
backup: backupGetExport deletes pinned, period(=30), issuer, account, digits(=6), algorithm(SHA1) — NOT folder
```

The backup path is the subtle one and it is correct: `backupGetExport` strips a list of defaultable fields including `delete entry.pinned`, but no `delete entry.folder` line was added, so folder names round-trip through cloud and file backups. Exports consumed by the upstream extension simply ignore the unknown field.

### Accordion gated on folder presence

`MainBody.vue` branches on `v-if="folders.length === 0"`. The true branch is the pre-existing dragula list copied unchanged — drake `entryDrake`, the four keydown focus handlers, the `EntryComponent` v-for over `entries`, and the `no-entry` empty state all preserved, confirmed against `git show dev:...`. The false branch renders `folderSections`: an Ungrouped section first (`entries.filter(e => !e.folder)`, labeled from `i18n.ungrouped`), then one section per sorted folder name, each a header that commits `accounts/toggleFolderCollapsed` and a `v-show` body keyed off `collapsedFolders`. Folderless entries land in Ungrouped because empty folder is falsy, so they never fall through to nothing.

The cost is that the false branch is not a dragula list, so when any folder exists there is no drag-reorder at all. The FEAT findings explain why per-section drakes were rejected: `dropModel` emits `dragIndex`/`dropIndex` against the flat `state.entries` array, and multiple per-section drakes over a folder-filtered, pinned-first presentation order would make those indices not correspond to real array positions, risking silent reorder corruption. Disabling reorder in the grouped view is the safe failure mode and the brief explicitly permitted it.

### Scope containment

No `archived` field, archive mutation, or archive UI anywhere in the diff. No manifest/name/short_name/icon changes — the only `+` lines matching name-like patterns are the i18n `folder_placeholder` strings. `scripts/credentials.ts` and cloud-backup auth are untouched. `LICENSE` remains the MIT text. The three new en strings (`folder`, `ungrouped`, `folder_placeholder`) are appended in the existing `{ message, description }` shape; other locales fall back to en.

### Test coverage

`src/test/models/storage.test.ts` backs `chrome.storage.sync` with an in-memory object and pins `storageLocation: "sync"`, then exercises the public path: `EntryStorage.set([entry])` → `EntryStorage.get()`, asserting a `"Work"` folder survives and an empty folder reads back falsy without throwing. This covers the exact set→get contract FEAT-001 promises.

Not tested: the import path (`EntryStorage.import` reading `folder`), the backup round-trip (`backupGetExport` not stripping folder), and all of the UI — the accordion grouping, Ungrouped placement, collapse toggle, and the no-folders drag-preservation path have no automated coverage. The optional component test was not added. And the storage test itself was not executed: the Puppeteer runner is non-headless with a hardcoded extension id and a bash `pretest`, so on Windows it was not run; the test is only proven to compile into the webpack test bundle.
